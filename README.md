# Diff Viewer · 文本对比器

![License](https://img.shields.io/badge/License-MIT-67e8f9)
![Dependencies](https://img.shields.io/badge/dependencies-0-a78bfa)
![Vanilla JS](https://img.shields.io/badge/Vanilla_JS-f0abfc)
![Size](https://img.shields.io/badge/size-~87KB-818cf8)

> 一个纯前端、零依赖的文本对比工具。左右一贴，差异立刻高亮。

玻璃拟态 + 磨砂渐变视觉风格。基于 LCS（最长公共子序列）的逐行差异算法，支持并排 / 统一两种视图、字符级内联高亮、忽略选项、上下文折叠，还能直接导出可用的补丁。

---

## 功能特性

### 差异对比

- **实时对比**：左右两侧输入框一改，下方差异立刻刷新（220ms 防抖）
- **行级差异**：新增 / 删除 / 修改 / 相同四种状态，配色区分
- **字符级内联高亮**：修改行内用更深的底色标出**具体改了哪几个字**，不用整行读一遍
- **两种视图**：
  - **并排**：左右对照，各自带行号
  - **统一**：合并成一栏，`−` / `+` 前缀，左右行号分列
- **改动导航**：`↑` / `↓` 按钮或 <kbd>Alt</kbd>+<kbd>↑↓</kbd> 在改动之间跳跃，当前改动有青色描边

### 忽略选项

| 选项 | 作用 |
| --- | --- |
| 忽略大小写 | `Hello` 与 `hello` 视为相同 |
| 忽略行首尾空白 | 缩进变化不产生差异 |
| 忽略所有空白 | 行内空格差异也忽略 |
| 忽略空行 | 空行不计入对比 |

> 「忽略所有空白」与「忽略行首尾空白」会自动互斥。

### 显示控制

- **行号**：可隐藏，得到更干净的对照视图
- **字符级高亮**：可关掉，只看整行差异（大文件更快）
- **仅显示改动**：只保留改动附近 3 行上下文，其余折叠成一行「⋯ 折叠 N 行 ⋯」，**点一下就展开**

### 导出

| 方式 | 说明 |
| --- | --- |
| **复制补丁** | 生成标准 unified diff 格式（`--- / +++ / @@`），可直接 `git apply` |
| **导出 HTML** | 生成自包含的对比报告，样式内嵌，单文件可分享 |
| **补丁下载** | 存成 `.patch` 文件 |

## 如何开始使用

**方式一：直接双击（最简单）**

双击 `index.html`，浏览器以 `file://` 方式打开。

**方式二：起一个本地静态服务器**

```bash
cd diff-viewer
python -m http.server 8000
```

然后访问 <http://localhost:8000>。

> 首次打开自带一份示例对比（一段 JS 代码的前后版本）。输入内容自动保存。

## 技术说明

### 零依赖

没有 `package.json`、没有构建步骤、没有 diff 库。全部逻辑在 `index.html` + `style.css` + `app.js` 三个文件里。

### 差异算法

引擎段位于 `app.js` 中 `/* ---ENGINE-END--- */` 之前，是不依赖 DOM 的纯函数。

```
文本 → 统一换行 → 按行切分 → 按选项归一化 → 映射为整数 id
     → LCS 动态规划回溯 → 合并为差异块 → 统计
```

| 环节 | 做法 |
| --- | --- |
| **行比较加速** | 两侧**共用同一张** key→整数 id 映射表，DP 只比整数，避免大文本反复比长字符串 |
| **LCS 回溯** | `Int32Array` 存 DP 表，按 `dp[i+1][j]` 与 `dp[i][j+1]` 选择前进来还原路径 |
| **超大文件降级** | 行数乘积超过 400 万时切换为「按 key 出现次数贪心配对」，保证不爆内存 |
| **块合并** | 连续的删除+新增合并为 `modify`，让字符级高亮能上下对齐 |
| **字符级对比** | 对 `modify` 块中左右对应的行再做一次字符级 LCS，标记出各自独有的字符 |

### 一个值得记的坑

最初两侧各自从 0 开始给行编号，结果 `"a"` 和 `"x"` 都拿到了 id `0`，DP 认为它们相等——**所有文本都会被判成"完全相同"**。修复方式是让两侧共用一张映射表（`makeIdMapper`），相同内容才拿到相同 id。自测里的「120 组随机对拍」就是专门守这条线的：相同行数必须严格等于 LCS 长度、两侧行数必须守恒。

### 性能保护

- 单次最多渲染 3000 行，超出提示改用导出查看
- 字符级高亮总字符超 20 万时自动整体放弃，避免卡顿
- 单行超 5000 字符时该行跳过字符级对比
- 2000+ 行文本实测在 3 秒内完成

### 数据存储

| 键名 | 内容 |
| --- | --- |
| `diff-viewer:left` / `diff-viewer:right` | 两侧文本 |
| `diff-viewer:opts` | 忽略与显示选项 |
| `diff-viewer:view` | 当前视图（并排 / 统一） |

## 小提示

- 「仅显示改动」在对比几十页的配置或日志时特别有用，一屏就能看完所有差异
- 导出的 unified diff 可以直接喂给 `git apply`，也可以贴进代码评审里
- 如果觉得字符级高亮晃眼，在「显示」里关掉它，只看整行差异会清爽很多
